Executive Summary

SecureVault is a production-grade, security-first encrypted file-sharing platform engineered for enterprises requiring verifiable confidentiality, integrity, and availability of sensitive documents. This report documents the complete Secure Software Development Lifecycle (SSDLC) covering all five phases: formal risk analysis, security architecture, hardened implementation, penetration testing, and compliance documentation.

The platform was subjected to a structured penetration test against a staging environment identical to production. No Critical vulnerabilities were found. Two High-severity findings were identified and remediated within 24 hours. The overall security posture is rated B+ (Good), appropriate for an enterprise SaaS security product.

Penetration Test Findings

Test Period: 2025-01-17 to 2025-01-24 | Methodology: PTES + OWASP Testing Guide v4.2 | Environment: Dedicated staging

PT-001
JWT Algorithm Confusion (RS256 → HS256)
High
CVSS 8.1
Remediated
CWECWE-327
VectorNetwork
PrivilegesNone
Fixed2025-01-18

The JWT library accepted both RS256 and HS256 algorithms. An attacker who obtained the RSA public key (often distributed via JWKS endpoint) could forge tokens by signing with HS256 using the public key as the HMAC secret, gaining arbitrary role claims including admin access.

GET /api/v1/auth/.well-known/jwks.json → RSA public key
jwt_tool --exploit k --pub public_key.pem -I -pc role -pv superadmin <token>
Before fix: HTTP 200 with admin access granted
After fix:  HTTP 401 "Token algorithm not accepted."

Fix: Added ALLOWED_ALGORITHMS: ["RS256"] to JWT configuration. All 8 algorithm confusion variants verified as rejected.

PT-002
IDOR — Unauthorized File Download
High
CVSS 7.5
Remediated
CWECWE-284
VectorNetwork
PrivilegesLow (user)
Fixed2025-01-18

The file download endpoint /api/v1/files/{id}/download/ returned files to any authenticated user regardless of ownership. By substituting a victim's file UUID, an attacker could download any file on the platform.

GET /api/v1/files/a1b2c3d4-.../download/  (User B's token, User A's file_id)
Before fix: HTTP 200 + presigned download URL
After fix:  HTTP 404 "File not found."

Fix: Added server-side verify_resource_ownership() before presigned URL generation. Returns 404 (not 403) to avoid confirming file existence to unauthorized users.

Lessons Learned & Future Work

Lessons Learned

Threat modeling pays dividends in pentest. Of the 12 pentest findings, 10 had corresponding risk register entries from Phase 1. The two surprises (JWT algorithm confusion detail, session ticket configuration) are being backported into the risk register for future projects.

Fail-safe defaults prevent severity escalation. The ClamAV integration's fail-safe design (reject on any error, including timeout) meant a ClamAV crash during testing didn't create a window for malware uploads. This is the right design.

IDOR is underestimated. PT-002 was a High-severity finding in an otherwise well-engineered codebase — found only because of systematic IDOR testing against every endpoint. Automated IDOR testing should be part of every CI/CD pipeline.
